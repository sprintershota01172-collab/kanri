# kanri — 考えなくても、整う。

iPhone / Android向け TODOアプリのソース一式と、手軽に操作できるWebプロトタイプ。

## フォルダ構成

- `native/` — Expo SDK 57 / React Native 0.86.3 によるネイティブ実装。SQLite、通知アクション、触覚、ドラッグ＆スナップ、テーマ切替。
- `web/` — ブラウザで動くオフライン対応PWAのプレビュー。ローカルストレージ利用。通知アクションは**非対応**。
- `icons/` — アイコンA（PNG）とB・C（SVG）を収録。推奨は **A: Folded K**。`native/assets/icon.png` に設定済み。

## 画面

| タブ | 操作 |
|---|---|
| FOCUS | 2×2象限。カードのタップで編集、長押しドラッグで象限移動。◇で最上位固定。象限内は2件ずつページ送り。|
| PLAN | 月・週・ガント切替。タスクの予定開始・納期・所要時間を表示。|
| PUZZLE | 未配置タスクをタップして枠を選ぶか、ドラッグして30分単位で予定化。重複・時間枠超過を拒否。取り消し対応。|
| SETUP | 優先度／グループの分類切替、4象限名編集、ダークモード、通知設定。|
| ＋ | タスク登録・編集。画面下地はリサイズせず、オーバーレイの上部に保存操作を配置。|

**注意:** 画面の縦スクロールを設けない方針のため、一覧はタスク件数に応じてページ送りします。極端に小さな画面・文字サイズのアクセシビリティ設定では、可読性は実機確認が必要です。

## 実機起動（ネイティブ版）

必要: Node.js 22.13以上、npm。iOSローカルビルドはMac + Xcodeが必要です。

```bash
cd native
npm install
npx expo install --fix
npm test
npx expo-doctor
npx expo start
```

- 実機の通知、触覚、ドラッグを確認するときは **development build** を推奨。
- Mac からiPhoneシミュレーターへ: `npx expo run:ios`。
- Androidエミュレーターへ: `npx expo run:android`。
- iPhoneへ配布するには、Apple Developerアカウントを用いた署名とEAS Build／Xcodeによるインストールが必要。現時点のZIPはIPA/APKではなく**ソースコード**です。
- SDK57をXcode27で使用できるよう `expo-build-properties` の `ios.enableSceneSupport` を有効にしています。

## ブラウザで試す（Web版）

```bash
cd web
python3 -m http.server 8000
```

PCから `http://localhost:8000` へアクセスします。PWAとしてiPhoneにインストールする場合はファイルをHTTPSホスティングへ配置してください。HTTPS配信でサービスワーカーがキャッシュを作成し、オフラインで利用できます。HTMLファイルを直接開いた場合、ブラウザによって保存・PWA登録の挙動が異なります。

**Web版とNative版はそれぞれ独立した保存領域です。自動同期しません。** Web版にはブラウザによる振動の試みのみがあり、iPhoneのOSローカル通知・通知アクションはネイティブ版だけです。

## 優先順位スコア

```
残り日数 D = 納期の日付 - 今日の日付
U = 納期なし 0、期限切れ 1、それ以外 1 / (1+max(D,0)/3)
P = (重要フラグ + 緊急フラグ) / 2
T = min(所要時間, 180分) / 180
B = 期限切れなら20、それ以外は0
Score = round(45U + 35P + 20T + B)
```

降順の自動整列。ピン固定したタスクを先に表示し、ピン内は手動順位順とします。「自動に戻す」はピンを外します。所要時間が長いタスクへの加点は、まとまった作業時間を確保するための方針で、必要なら設定可能な重みに変更できます。

## データ保存

- ネイティブ: `kanri.db` に `tasks`（JSONペイロード）、`meta`（設定）をSQLite保存。WALモード。ログイン・サーバー不要。
- Web: `localStorage` の `kanri_v1_tasks` / `kanri_v1_prefs` に保存。PWA用サービスワーカーを同梱。
- 通知は `expo-notifications` が端末OSの予定通知として予約。設定ON時だけ権限要求。予定変更・完了時に旧通知をキャンセルし再スケジュール。
- 通知の「完了」「10分後スヌーズ」はタップするとアプリが開き、アクション処理を実行。iOS/Androidの機種設定により到達時間や動作に差があります。

## 動作確認シナリオ

1. `＋` から3タスクを作成。重要・緊急フラグの4象限への分類を確認する。
2. 期限を当日・明日・7日後にして優先度順を確認する。◇ボタンで最上位に固定し、「固定を解除」で元に戻す。
3. カードを長押しし別象限に移動。分類フラグも更新されることを確認する。
4. SETUPから「グループ」へ変更。象限名を編集し、アプリ再起動後も保存を確認する。
5. PUZZLEで60分ブロックを10:00へ配置し、近接重複枠に別ブロックを入れると拒否されることを確認する。
6. PLANの月・週・ガント各表示に予定が現れることを確認する。取り消しで消えることを確認する。
7. 通知をON。納期を設定し通知タイミングを『自由入力（分前）』で調整して通知を待ち、「10分後」または「完了」で操作する（納期通知はその日の23:59を基準に指定分数だけ前倒し。予定開始通知はスロットで設定した開始時刻を使用）。
8. 機内モードで起動し、追加・編集・完了を実施。再起動してデータが残ることを確認する。
9. 入力時に背後のボードが移動しないこと、画面全体に縦スクロールが出ないことを確認する。
10. iPhone小型機／大型機／Androidで文字切れ・画面サイズ・60fpsの体感を確認する。

## 現在の検証範囲とリリース前の残作業

実施済み: TypeScriptファイルの構文変換検査、Web版JSの構文検査、モデル単体テスト7件。
未実施: npm依存解決・TypeScript完全型検査・ネイティブビルド・実機UI・通知／スヌーズの通し試験・FPS測定。
共有要素（カードから詳細へ形状が連続変化する厳密なトランジション）は未搭載。編集シートはスプリングで表示します。
ユーザーが任意のタスクを自由に並べるドラッグ順序UIも未搭載ですが、◇による手動最上位固定・ピンの解除に対応します。
現状は**実行可能な実装ソース＋Webプロトタイプ**であり、App Store提出済み／品質保証済みではありません。

## GitHub Pages で Web 版を公開

このリポジトリは `web/` を GitHub Pages に自動デプロイする GitHub Actions を同梱しています。
GitHub の **Settings → Pages → Build and deployment → Source** で **GitHub Actions** を選択すると、`main` の更新後に Web 版を配信できます。
設定後のURLは `https://sprintershota01172-collab.github.io/kanri/` です。GitHub Actions のデプロイが成功するまでは公開URLを動作確認済みと扱わないでください。

GitHub Actions では `native/scripts/test-model.cjs` のモデルテストも実行します。ネイティブアプリの実機ビルド・通知試験まで自動確認されるわけではありません。

**注意:** GitHub にソースコードを公開しても、端末に保存されたタスクデータが公開されることはありません。公開リポジトリへパスワードやAPIキーをコミットしないでください。
